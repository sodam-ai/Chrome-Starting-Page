1. Project Overview

Chrome Starting Page Dashboard replaces your Chrome "New Tab" / start page with a personal dashboard that brings together:

  • Category-organized bookmark cards — drag-to-reorder, automatic favicon lookup, dead-link detection
  • Notes — multiple independent note cards with lightweight Markdown (bold/links/code)
  • To-do lists — priorities, due dates, recurring tasks, tags, a kanban board
  • Calendar — month/week views, recurring events, reminders
  • Pomodoro timer — automatic 25-minute focus / 5-minute break cycles
  • Habit tracker — daily check-off with streak tracking
  • Spotlight universal search (press F) — search bookmarks, todos, and notes at once, plus a >command palette

The three things that matter most

  1. 100% local-first. This project is a tiny web server (server.js) that runs only on your own machine, serving a single page (index.html). Every piece of data is stored purely as JSON files inside this project's own data/ folder. There is no cloud backend, no account, no login.
  2. Zero external dependencies. package.json has no dependencies field at all. The server is built entirely on Node.js's built-in modules — no npm install step is required.
  3. MIT License — commercial use is allowed. This software may be used, modified, redistributed, and even sold, personally or commercially, for free. See Section 18 for the exact terms.

5. How to Install

🪟 Windows

  1. Open the downloaded folder.
  2. Double-click setup_windows.bat. (No administrator rights needed, no system files touched.)
  3. A black console window runs through these steps automatically:
StepWhat the script does
1If you already have data, it's safely backed up first (data\backups\safety-before-setup.json). On a fresh install, it creates data\, data\backups\, data\icons\, data\profiles\, and assets\
2Checks for Node.js: portable copy first, then system install; downloads a portable copy (v22.19.0) automatically if neither exists
3Safely stops any previously running instance, if one exists
4Registers auto-start at login (Windows registry key HKCU\Software\Microsoft\Windows\CurrentVersion\Run; falls back to a Startup-folder shortcut)
5Starts the server hidden, with no visible window
  1. The final message shows the real address (default http://localhost:1111 — may shift to 1112, 1113, etc. if busy).
  2. You can close this window — the server keeps running in the background.
Note: Aside from one login auto-start entry, this installer never touches system files or Chrome's own policies/registry. Pointing Chrome at this page is a separate step you do yourself — see step 4 of Quick Start.

🍎 macOS

  1. Install Node.js first if needed (Section 3).
  2. Open Terminal.
  3. Navigate to the project folder: 
    cd ~/Downloads/chrome-starting-page   # adjust to your actual path
  4. Run the setup script: 
    bash setup_mac.sh
  5. This generates a LaunchAgent (com.dashboard.startpage.plist), installs it into ~/Library/LaunchAgents/, loads it, and starts the server. The app starts automatically on login and restarts itself if it ever crashes (KeepAlive — not present on Windows).
  6. The final message shows the address to open (e.g. http://localhost:1111).

8. How to Use

8.1 Search & Spotlight

  • Type in the top search bar and press Enter to search with your default engine (configurable in Settings).
  • Prefix with a keyword to jump to a specific engine: yt cats, nv weather, gh react (defaults: yt, nv, gh, g, tw, map).
  • Press F to open Spotlight, searching bookmarks, todos, notes, and D-Days at once — including Korean chosung search.
  • Inside Spotlight, type > commands: >todo, >timer 15, >focus Work, >add Name URL, >habit, >today, >kanban, >layout, >settings, >theme, >export.

8.2 Bookmarks

  • Add/edit/delete inside category cards, drag to reorder or move between categories/pages.
  • Right-click for: pin to top, edit, open in new tab, open whole category, move to page, delete.
  • Drag a URL out of the address bar onto a card to add it instantly.
  • Paste (Ctrl+V) a copied link anywhere to get a "which category?" popup.
  • Items added in the last 7 days get a "NEW" badge; frequently/recently used ones can auto-sort to top.
  • Dead links are flagged after 3 consecutive failed checks.
  • Deleted items go to Trash for 30 days.

8.3 Notes

  • Independent note cards, rename by double-clicking.
  • Auto-linkifies URLs; supports **bold**, `code`, [text](url) preview.

8.4 To-do

  • Multiple cards, 4 priority levels, due dates, tags, subtasks.
  • Recurring todos (daily/weekdays/weekly/monthly).
  • Kanban board or full list view.
  • 100% completion triggers confetti; streaks are tracked.

8.5 Calendar

  • Month/week views; click a date to add an event; prefix ! to add a to-do instead.
  • Recurring events (weekly/biweekly/monthly); browser reminders 10 minutes ahead.

8.6 Pomodoro & Habit Tracker

  • Optional 25 min focus / 5 min break auto-cycle (15-min break every 4th session); can start from a to-do item.
  • 7-day focus chart.
  • Habit tracker: list habits in Settings, check off daily, streaks tracked.

8.7 Personalizing the Look (⚙ Settings → Visual)

  • Dark/light toggle or "follow system"; 6 accent colors.
  • Background slideshow (1 min–24h interval); 3 glass presets; adjustable blur/opacity.
  • 4 layout presets; sanitized custom CSS injection (see Section 15).

9. How It Works

In one sentence: the browser asks a small server running on your own machine to "save this" or "load that," and the server writes/reads it as JSON files under data/.

  1. Opening it: your browser requests http://localhost:<port>/ → the server serves the page → it immediately requests its own data via /api/bookmarks, /api/notes, /api/config, etc.
  2. Changing something: the page waits ~0.3–1s (batching rapid changes) before saving. The server writes to a temp file then renames it into place (atomic write) so files never end up half-written.
  3. If the connection drops: an "offline mode" banner appears; changes are held in localStorage and auto-saved once reconnected. Nothing is lost.
  4. Multiple tabs: saving in one tab broadcasts a refresh signal to others via BroadcastChannel.
  5. Offline loading: a service worker (sw.js) pre-caches the 4 static files; /api/... requests are never cached and always go live.
  6. Self-management: integrity checks and auto-recovery on boot, daily automatic backups (30-day retention, 50 max), automatic port fallback if busy.

13. Workflow

[One time]
  Download → run the installer → auto-start registration is done
       ↓
[Every day after that]
  Turn on your computer
       ↓ (Windows: registry Run key / macOS: LaunchAgent starts the server)
  The server waits quietly in the background
       ↓
  Open a new Chrome tab, or visit http://localhost:1111
       ↓
  Use bookmarks/todos/notes/calendar as normal
       ↓ (auto-saved after a short debounce)
  Server writes to data/*.json (atomic writes + automatic backups)
       ↓
[Shutting down]
  The server shuts down too (a final backup runs on a clean exit)
Data looks wrong
   → Settings → Data tab → pick a backup → Restore
   (or) integrity checks on every boot often self-heal a corrupted file

14. Architecture

┌───────────────────────────┐        HTTP (127.0.0.1:port)         ┌──────────────────────────────┐
│   Browser (Chrome, etc.)   │ ───────────────────────────────▶  │  Local server (server.js, Node) │
│  index.html / script.js     │ ◀─────────────────────────────── │  Node built-in http module only  │
│  style.css / sw.js            │      static files + /api/* replies  │  zero npm dependencies             │
│  localStorage (offline cache) │                                    │  bound to 127.0.0.1 only           │
└───────────────────────────┘                                    └───────────────┬────────────────┘
                                                                                    ▼
                                                                     ┌───────────────────────────┐
                                                                     │   data/*.json (file storage) │
                                                                     │   atomic writes + auto backups│
                                                                     └───────────────────────────┘
  • Frontend: plain HTML/CSS/JavaScript, no framework. Reads/writes through /api/*, falling back to localStorage only when unreachable.
  • Backend: a single Node.js process on the built-in http module. No database — every piece of data is a JSON file.
  • Auto-start layer: a Windows registry Run key or macOS LaunchAgent — purely OS-level auto-launch, never touches Chrome.
  • Offline layer: the service worker caches only 4 static files; /api/* is always network-first.

15. Security / Data Flow

15.1 Every external destination this app talks to

DestinationWhenWhy
fonts.googleapis.com, fonts.gstatic.comEvery page loadUI fonts
google.com/s2/favicons, icons.duckduckgo.com, icon.horse, the site's own faviconWhen a bookmark scrolls into view4-step favicon fallback chain
api.openweathermap.orgOnly if you entered a weather API keyWeather widget
Your own bookmark URLsPeriodically (dead-link check)HEAD request only, checking reachability
Google/Naver/YouTube/etc.Only when you searchNormal browser behavior

That list is exhaustive. No ads, analytics, tracking, or "phone-home" telemetry exists. The only automatic internet access anywhere is the Windows installer's one-time official Node.js download when Node.js isn't present.

15.2 Security properties of the server itself

  • Only accepts connections on 127.0.0.1 — no other device can ever reach it.
  • Never makes outbound calls to the wider internet — the only "network activity" is a loopback shutdown call to a previous instance of itself.
  • No authentication — by design, for a single-user local tool; other local programs on the same machine could reach the port.
  • Path-traversal blocked on every upload/import/export path.
  • Custom CSS is sanitized before it's applied.
  • Upload requests capped at 10MB.

15.3 Where exactly is my data?

Entirely inside this project's own data/ folder, as plain JSON. Nothing auto-syncs anywhere; copy the folder to move it, delete it and the data is gone (hence the automatic backups).

17. FAQ

Q. Can I use this commercially?
A. Yes — MIT-licensed. Use, modify, redistribute, even sell it, as long as you keep the copyright notice. See Section 18. (Plain-language summary — the LICENSE file is authoritative.)

Q. Does it work offline?
A. Yes, fully, except fonts/icons/weather which need internet to display.

Q. Is my data sent anywhere?
A. No. Section 15 lists every external contact this app ever makes.

Q. Does this replace Chrome's actual New Tab page?
A. Not automatically — you register it yourself under chrome://settings/onStartup.

Q. Can I access it from my phone or another PC?
A. No — it only binds to 127.0.0.1, by design.

Q. How do I move my data?
A. Export (JSON) from Settings → Data, then Import on the new machine, or copy the data/ folder directly.

Q. Do I need to understand Node.js?
A. Not on Windows (auto-installed). On macOS, install it once and forget about it.

Q. Can I recover something I deleted?
A. Yes — Ctrl+Z right after, or Trash (30-day retention) later.

Q. How do updates work?
A. No auto-update check exists — download the newer version and keep your data/ folder.
